# 总控会话（codex://threads/01a0ceec-5cfc-7190-baa1-8ed8d255e616）为什么执行成这个样子

> 分析人：project-flow-az 主仓会话 thread=01a0d72d-be82-7b33-be15-2f3bf97d7e05
> 分析时间：2026-09-26　证据源：该 thread 的 5 个 rollout jsonl（~/.codex/sessions/2026/09/2*/）
> 结论性质：机制诊断（可复现），不是推测。

## 0. 一句话结论

**用户看不到汇报和看板，不是模型没写，而是「写了的被自己盖掉了」——而且是被自己的内部思考草稿盖掉的。**
根因：`flow-budget.py` / `flow-boot.py` 判定「上轮有没有贴看板」时，读的是 `task_complete.last_agent_message`，
而**在部分（长）会话里这个字段装的是模型原始输出（含 `<analysis>`/`<thinking>` 草稿），不是用户看到的正式回复**。
于是两个错误同时发生：① 机检读到的是一坨草稿，判「没贴看板」→ 每轮开工都念叨；② 用户真正想看的汇报被草稿挤掉。

---

## 1. 用户的两个抱怨，逐一坐实

### 抱怨 A：「我要的汇报和任务看板，都没有什么玩意儿啊」

**实测该 thread 的 3 个收工点：**

| rollout 文件 | last_agent_message 长度 | 含「任务状态看板」 | 以 `<analysis>` 开头 |
|---|---|---|---|
| 2026-09-23T23-39-51 | 17,166 | ❌ | ✅ |
| 2026-09-25T00-44-51 | 25,680 | ❌ | ❌ |
| 2026-09-25T20-10-36 | 33,805 | ❌ | ✅ |

`3 / 3` 全部不含看板。也就是说：**在这条总控线上，看板一次都没进过"对外回复"**——
而 `flow-deliver.py` 大概率每次都跑了、也每次都把看板打印到了自己的 stdout，然后**被同一轮的草稿吞掉**。

### 抱怨 B：「所有的用户消息又出现了，整那么多这个东西有什么用呢？」

实测 `last_agent_message` 里出现「用户消息 20」等编号 **5 次**（`['20','19','20','20','20']`）。

**这些不是模型在回复里复述用户话**，而是模型**在给自己写上下文摘要**时，按时间顺序回放了整段对话
（"**Message 1 (user):** A project-flow relay prompt requiring…"）。
它出现在 `<analysis>` 段里，是模型内部的"捋一遍对话"动作。

**为什么这直接违反规则**：接力提示词和 AGENTS.md 都写了硬规则——
> 「交接棒与汇报只写『规格点 / 待办 / 证据 / 下一步』，**禁止把用户消息原样贴进来**」

规则被违反了，但违反者不是"交接棒"，而是**模型的思考草稿泄进了对外回复**。

---

## 2. 根因：`last_agent_message` 装错了东西

### 2.1 机检的假定（写在代码注释里，是明确契约）

`scripts/flow-budget.py`：

```python
def last_visible_reply(paths: list[Path]) -> str:
    """取该 thread 最后一轮**用户可见的回复**。

    `task_complete.last_agent_message` 就是那一轮的对外回复，是判断
    「熔断提示词有没有真的贴给用户看」的唯一可靠依据。
    """
```

机制是对的，**前提是那个字段真的等于"用户可见的回复"**。

### 2.2 现实：它等于"模型的原始产出"

三条实测证据：

1. 本会话（project-flow-az）的 `last_agent_message` 开头是：
   `<thinking>(this turn ran without thinking mode)</thinking>\n<thinking>…</thinking>\n\n证据齐了，回答你的问题。`
   ——连 **thinking 块都原样装进去了**。
2. 总控会话的 `last_agent_message` 是 **33,805 字符的 `<analysis>` 草稿**，正文是
   "Let me chronologically work through this conversation." 这种模型自述。
3. 总控会话尾部是可选的"下一步"规划段落，全是模型内部推演，**没有一句是给用户看的**。

**结论：这个字段在不同会话/不同长度下语义不稳定。**
短会话（如本会话 2,357 字符）它接近正文；长会话它退化成草稿。而总控这种"20+ 用户消息、
每轮都写 SDD 台账"的重会话，**必然**踩中退化形态。

### 2.3 于是形成了闭环死锁

```
模型把看板写进 stdout （✓ 做了）
      ↓
该轮对外产出被 <analysis> 草稿覆盖
      ↓
last_agent_message = 草稿，不含「任务状态看板」
      ↓
下一轮 flow-boot 机检：board_visible=False → 「上轮回复缺失任务看板」
      ↓
用户看到的是"你又说我没贴看板"，但这次模型连看板都没写进"对外回复"里
      ↓
（回到第一步，永动机）
```

这个闭环**正是 `PFP-REPORT-VISIBILITY-20260925` 想修的东西**，但它只修了"渲染"和"有没有机检"，
**没修"读的那个字段到底准不准"**。我本次的 4.15.19 也没修到这一层。

## 3. 为什么总控会话比别的会话更严重

总控线程的形态天然放大这个缺陷：

| 特征 | 后果 |
|---|---|
| 20+ 轮用户指令，每轮都要求「首行报告 xxx + flow-deliver 三段看板」 | 每轮都产生大段结构化输出 → 更易退化 |
| 每轮都要写 SDD 交接棒 + 规格台账 | 输出量再翻倍 |
| 用户在拍板、验收、打回之间反复切换（PMO 角色） | 对话回放冲动最强（"让我按时间顺序捋一遍"） |
| 并发会话（`01a0c297`）反复写坏交接棒 | 模型要花大量篇幅解释"我被阻塞了" |

最致命的是第 3 条：**用户每次问"结果是什么呢，任务看板呢"，都是在追问被草稿吃掉的那一份。**
而模型下一轮又用同样的方式回答 → 用户感觉"问了 10 次都没给我东西"。

---

## 4. 这不是模型的"态度问题"

值得单独指出，避免误判为"模型偷懒"：

- 该会话**确实做了大量真实工作**：修 `flow-boot.py` 两个缺陷（孤儿回执引用、属主回退跳过）、
  `16/16` 测试通过、提交 `4d00f76`（192 文件）、`aa7bff3`/`06e720f`/`737bf02` 三个分支抢救提交、
  跑 `verify_w2_acceptance_recycle.sh` `PASS=13 FAIL=0`。
- 这些工作在 `last_agent_message` 里**全部有记录**，只是记录形态是"模型自述"而非"给用户看的汇报"。

**所以问题是交付管道，不是工作质量。**

## 5. 修复建议（按性价比排序）

### P0：机检不许读草稿

`last_visible_reply()` 取到 `last_agent_message` 后，**先剥掉 `<analysis>` / `<thinking>` 段**，
再判断 `board_visible`。剥完如果为空，应判定为"不可判定"而不是"没贴看板"——
**把假阳性（冤枉模型）和真缺失（模型真没贴）区分开**：

- 剥完非空且无看板 → 真漏贴，照旧点名（现有行为，正确）；
- 剥完为空 / 全是草稿 → **不可判定**，不点名、不阻塞，改为在开工状态里标注"上轮产出无法解析"。

这一条能立刻止住"每轮开工都念叨"的噪音。

### P1：`last_agent_message` 语义不稳定要绕开

既然该字段长度/形态随会话而变，**不应该用它作为唯一真相源**。
更稳的观测量是 `response_item` 里 `role=="assistant"` 的最后一条 message
（本次实测：本会话 21 条 assistant message，最后一条就是给用户的正文）。
`last_visible_reply()` 应优先用后者，`last_agent_message` 只作回退。

### P2：把「看板必须可见」变成结构化断言，而不是字符串匹配

现在 `BOARD_MARKERS = ('任务状态看板', '当前聚焦待办')` 是两个中文词的 `in` 判断。
模型在草稿里提到这两个词（比如本次的"是否含「任务状态看板」"）也会被判为"贴了"。
应改为：**四个分区标题全在**且**顺序正确**（对齐 `flow-deliver.py` 的固定契约）。

### P3：给长会话一个"汇报不占正文"的出口

总控这种重会话，每轮都要在正文里塞四状态看板 + 工作汇报 + 验收卡，
本身就把正文挤爆、逼模型把内容往草稿里放。
可考虑：**看板只写 `flow/看板.md` + 回执，正文只贴'本轮工作汇报'三段**（用户在意的其实是"干了什么"），
让 `flow-deliver.py` 的落盘成为唯一真相源，正文按需引用。
