# 自动版本接管与无感热更新 SOP (Auto Hot-Sync & Version Takeover SOP)

> 解决痛点：全局 Skill 升级后，历史老项目依旧停留在旧版规范，导致新特性无法生效、多项目版本割裂的问题。**触发即检测、无感热同步、非破坏平滑升级！**

---

## 1. 核心触发机制 (Trigger on Invocation)

当用户在任何已有项目（已存在 `flow/` 或 `AGENTS.md`）中触发 `project-flow-az`、`project-flow-cy`，或者执行日常指令（如开工读取规则、初始化、状态流转）时：

1. **版本嗅探 (Version Sniffing)**:
   - 读取全局 Skill 的 `VERSION`（如 `v2.1.0`）；
   - 读取目标项目本地 `flow/规范/VERSION`（若文件不存在，则视作 legacy 旧版 `v1.0.0`）。
2. **差异判定 (Diff Judgment)**:
   - 若 `本地版本 < 全局版本` 或 `本地版本不存在`：
   - **立即触发无感热更新 (Non-destructive Hot-Sync)**。

---

## 2. 无感热更新执行标准 (Hot-Sync Standard)

热更新必须遵循**非破坏性 (Non-destructive)** 铁律：

```
                    ┌────────────────────────────────────────┐
                    │    全局 Skill 升级 (v2.1.0 发布)       │
                    └───────────────────┬────────────────────┘
                                        │ 任意项目触发协作
                                        ▼
                    ┌────────────────────────────────────────┐
                    │     版本嗅探: 本地版本 < 全局版本      │
                    └───────────────────┬────────────────────┘
                                        │
             ┌──────────────────────────┴──────────────────────────┐
             ▼                                                     ▼
     【第一步: 规范与结构热同步】                             【第二步: 运行时合同增量升级】
     · 覆盖更新 flow/规范/ (方法论副本)                       · 增量更新 AGENTS.md / CLAUDE.md
     · 确保补齐 flow/history/ 与 flow/trash/ 物理隔离目录     · 注入四状态机看板协议与双轨回收规则
     · 刷新 flow/规范/VERSION 写入最新版本号                  · 保留用户原有项目自定义业务规则
```

### 步骤 1: 规范与结构补齐
- **方法论详规覆盖更新**：将全局 Skill `references/` 下的最新 8 份详规完整同步覆盖至项目的 `flow/规范/`；
- **目录结构无损补齐**：若项目缺失 `flow/history/`（完结归档库）或 `flow/trash/`（废弃隔离堆），立即自动补建，不删除任何原有已有内容；
- **版本号落盘**：将最新版本写入 `flow/规范/VERSION`。

### 步骤 2: 运行时合同 (`AGENTS.md`) 增量升级
- **无损块更新**：若 `AGENTS.md` 中存在 `<!-- project-flow-cy:start -->` 与 `<!-- project-flow-cy:end -->` 标识，仅更新标记块内的运行时合同；
- **规范能力就绪**：注入最新的【四状态机看板与提请验收卡】、【双轨回收机制】、【高风险人工决策升级门】及【按需销账】协议；
- **绝对保留业务逻辑**：绝不覆盖或抹除用户自行编写的业务技术栈、模块说明和子项目专用指令。

### 步骤 3: 极简感知通知
在当前轮次首屏输出中以 1 行状态提示通知用户，不阻碍主任务执行：
```markdown
💡 [project-flow-az] 检测到全局协作 Skill 升级，已自动为当前项目热同步至 v2.1.0 规范体系。
```

---

## 3. 防破坏边界 (Safety Boundaries)
1. **严禁清空历史数据**：热同步严禁动用户的 `flow/plan.md`、`flow/进展.md`、`flow/decisions.md`、`flow/踩坑记录.md` 活跃数据；
2. **严禁篡改业务源码**：只同步控制层规范 (`flow/规范/` 与 `AGENTS.md` 规范标记块)，不触碰任何代码文件；
3. **幂等保障**：相同版本重复触发直接跳过，零额外开销。
