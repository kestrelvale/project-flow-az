# 纠偏提示词 · 交接自包含（给「接手别人交接」的新会话）

> 用法：新会话第一轮就直接贴这段（可把 `<工作根>` / `<ticket>` 换成实际值）。
> 依据：2026-09-24 实测 thread `01a0d08b` —— 接力提示词只带相对路径与 `<ticket>` 占位符，
> 用户把它贴进主仓新会话，结果新会话读错项目的 plan/进展、再去 git worktree / claims / 源码里
> 找「P4 到底在哪」，75 次工具调用遍历历史。本提示词治的就是这个。

## 0. 先对齐位置（最重要）
- 本次交接的**工作根**是 `<工作根>`（例如 `/Users/chinkinoko/projects/<proj>-worktrees/wt-p4`），
  **不是** `<主仓路径>`。开工前先 `cd <工作根>`，之后所有 `flow/...` 路径都相对它解析。
- 本次交接的**任务卡**只有一张：`<工作根>/flow/tasks/<ticket>.md`
  （例如 `W2-P4-CANDIDATE-H5-20260922`），台账是 `<工作根>/flow/specs/<ticket>.md`。
- 主仓/其它工作区的 `flow/plan.md`、`flow/进展.md` 顶部那条**不是本次任务**，不要当任务读。

## 1. 硬首动 + 只读范围
```
cd <工作根> && python3 ~/.codex/skills/project-flow-az/scripts/flow-boot.py . --intent "<本轮任务摘要>"
```
只读这些（其它一律不读）：
- `<工作根>/flow/plan.md` 的当前聚焦 `[ ]`/`[✕]`
- `<工作根>/flow/进展.md` 顶部一条（本次交接棒）
- `<工作根>/flow/tasks/<ticket>.md`
- `<工作根>/flow/specs/<ticket>.md` 里**状态不是 `[x]`** 的规格点
- 与当前阶段匹配的 `<工作根>/flow/规范/*.md`

**不要**：遍历其它任务卡、其它 worktree、`flow/history/`、`flow/trash/`，
也不要为了「确认自己在哪」去 `git worktree list` / 读 `flow/claims/` / 翻源码历史 ——
工作根与任务卡已经在上面点名了。

## 2. 交接要「说清楚」，不要「省字数」
- 交接棒**没有字节上限**（v4.15.16 起）：逐页明细、证据清单、路径与命令该写就写。
- 唯一不许写的是**用户消息原文照抄**（判据：最长连续照抄 >= 400 字符或比例 >= 60%）——
  那是「复述历史」，不是「交接规格」。
- 四字段「现状 / 还剩 / 卡在哪 / 下一步」+ 顶部 `thread=<CODEX_THREAD_ID>` 必须齐全。

## 3. 熔断（STOP）时的正确收尾
1. 把规格点与待办蒸馏进 `<工作根>/flow/进展.md` 顶部交接棒 + `<工作根>/flow/specs/<ticket>.md`；
2. 跑 `python3 ~/.codex/skills/project-flow-az/scripts/flow-budget.py --print-relay --project .`
   把输出的「project-flow 接力提示词」**原样贴进回复**（只写「已熔断」不算交接）；
3. 结束本轮，**开新会话**续跑 —— 不要在同一个（已到 60%+ 上下文的）会话里继续施工，
   否则熔断等于白做。

## 4. 判定「这一轮做完了没」
- 只做台账里未回收的规格点；`[x]` 不得重跑、不得假销账（`[x]` 必须带证据）。
- 交付类收尾：改动绝对路径 + `Exit 0` 原文 + `flow-deliver.py` 三段（看板 / 工作汇报 / 交付验收卡）
  原样贴进回复，缺一段都不算交付。
