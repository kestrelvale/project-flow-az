# 规格点回收台账 · 模板
#
# 用途：把用户需求蒸馏成「要执行的规格点」，逐条回收状态与证据。
# 位置：`flow/specs/<ticket>.md`（与任务卡的 ticket_id 同名）。
# 为什么需要：实测 2026-09-21 的 P0/P4 会话中断后，同一个需求点被反复执行——
#   没有销账台账，「做完了没」只能靠重读历史猜，而重读历史正是上下文爆炸的起点。
#
# 行格式（flow-gate / flow-distill 都按这个正则读，不要改）：
#   - [状态] SPE-编号 | 规格点（可观察的结果） | 证据：<可复现的凭证>
# 状态：`[ ]` 未做 / `[-]` 进行中 / `[x]` 完成 / `[!]` 阻塞
# 硬规则：
#   - `[x]` 必须带证据，否则视为假销账，门禁与交付都会拒绝；
#   - 进入 review/handoff 前不得有未回收项；
#   - 只做未回收项，标记 [x] 的完成项不得重跑；
#   - 规格点来自用户需求，但**不许原样照抄用户原话**——要写成「可观察的结果」。

- [ ] SPE-1 | <规格点：可观察的结果> | 证据：
- [ ] SPE-2 | <规格点：可观察的结果> | 证据：
- [!] SPE-3 | <被阻塞的规格点> | 证据：<阻塞证据> / 解除条件：<…>
