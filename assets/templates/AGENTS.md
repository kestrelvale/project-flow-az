# <PROJECT_NAME> · 协作约定(Claude Code / Codex 共用入口)

> `CLAUDE.md` 软链到本文件，两端读同一份规则入口。**代码与架构产出落盘实体文件，用户的当面指令是最高执行意图。**

## 目录地图(哪个文件夹放什么)
- 根级 `flow/` — 唯一控制层(项目"怎么跑"): `charter.md` 目标 / `plan.md` 活跃计划(当期 SDD 原子规格清单) / `进展.md` 进展日志(顶部=最新交接棒,仅留1~2条)/ `decisions.md` 决策日志 / `踩坑记录.md` 问题与经验库 / `tasks/` 多端独立任务卡 / `history/` 历史完结与日志滚动归档区(供追溯) / `trash/` 废弃与垃圾物理隔离区 / `规范/` 方法论详规
- 根级 `docs/` — 集中内容层(项目"做出什么"): 产品 / 架构 / `contracts/` 跨模块契约 / `modules/` 模块说明 / 评审和产出说明
- `<子项目>/`、`scripts/` 或 `src/` — 代码、静态原型、组件与构建配置;有独立职责的端/子项目用局部 `AGENTS.md` + `CLAUDE.md` 记录本模块规则
- `DESIGN.md` — (可选)设计 / 创意决策
- **判据**: 协调 / 推进总体项目的 → 根级 `flow/`; 需要统一发现的知识和方案 → 根级 `docs/`; 代码与原型 → 对应端/子项目。默认不在子项目中重复建 `flow/` 或 `docs/`

## 🎯 核心铁律一: 任务四状态机与 SDD 规格驱动原子拆解 (Task State Machine & SDD)
任务必须严格遵循四种状态，**且任何实质性回复第一屏必须强制输出独立代码块 To-Do 清单看板与提请验收卡**：
1. **`[ ]` 待完成 (TODO)**: 用户当前会话下达的任务为 **最高优先级 (P0)**。面对复合多子项需求，必须按照 **SDD (规格驱动设计)** 拆解为原子 To-Do (P0-1, P0-2...)，锁死 I/O 契约与写入边界白名单，立即进入执行。
2. **`[-]` 待验收 (Pending Verification)**: 代码已落盘且通过专属自动化微单测（<3s, Exit 0, 0 Error, 截图存盘），等待用户确认。**低优先级/绝对静默状态，Agent 严禁自发重复执行、严禁反复排查、不要去管它**！
3. **`[✓]` 已完成 (Done)**: 用户验收确认通过，彻底完结。**必须立即在当回合第一指令从 `plan.md` 物理剪切移入 `flow/history/`**，活跃看板零留存已完成文本。
4. **`[✕]` 不合格 (Rejected)**: 用户验收判定不合格。**最高优先级 (P0)**，本次会话必须立即针对缺陷进行重构修改，修复后转为 `[-]` 待验收。
5. **首屏代码块 To-Do 清单协议**: 回复第一段必须输出独立 Markdown 代码块包裹的 To-Do 看板（明确区分 `[🤖 自动测试通过]`、`[👤 待人工验收]`、`[⚡ 自动决策]`），交付时显式给出包含 **Given-When-Then** 操作步骤的【提请验收卡】。

## ⚡ 核心铁律二: 任务按需加载与动态销账机制 (On-Demand Loading & Dynamic GC)
1. **多子任务逐项销账 (In-Prompt Pruning)**: 复合多子项任务攻克一项即打标 `[✓ P0-x DONE -> PRUNED]` 并从当前注意力中彻底剥离，后续轮次仅聚焦未完成项，杜绝上下文膨胀与死循环复读。
2. **物理即时回收 (Mandatory Physical GC)**: 用户一旦确认通过，Agent 在当回合**必须第一优先执行文件剪切指令**将任务移入 `flow/history/`，严禁口头归档但文件不剪切。
3. **分级回收机制 (Two-Tier GC)**:
   - **自动回收 (Automated GC)**: `flow/进展.md` 活跃区仅保留最新 1~2 条记录，超出自动滚动截断至 `flow/history/进展_YYYYMM.md`；临时探测脚本执行完毕自动移入 `flow/trash/` 或清理。
   - **人工确认回收 (Human Confirmation GC)**: 业务交付物必须先挂起为 `[-] 待验收`，用户显式确认通过后才物理剪切移入 `flow/history/`，严禁 Agent 自作主张自动销账。
4. **双轨决策与升级门 (Decision Gate)**: 局部代码实现细节由 Agent 自主决策并记入 `decisions.md`；架构破坏/高风险改动触发人工决策卡，等待用户确认。
5. **多端分卡与白名单切片 (Domain Queueing)**: 单仓多端项目的待验收任务存放在 `flow/tasks/<模块>.md` 独立维护。做当前端时**严禁读取无关模块的任务卡**，彻底阻断历史任务复读。
6. **指针交付原则 (Pointers Only)**: 凡超 20 行的长文、全套法条或文书，一律直接写入实体文件，聊天窗口仅输出极简看板、核心结论（≤20行）与文件绝对路径。
7. **快速通道 (Fast Track)**: 日常单点修改、UI 微调、单点 Bug 修复直接修改代码验证，不被重型流程阻碍。

## 🤖 核心铁律三: Sub-Agent 蜂群架构与双引擎自适应降级 (Sub-Agent Swarm)
1. **主控架构师唯一控制面 (Orchestrator Sole Ownership)**:
   - 只有主控 Agent 拥有 `flow/`（`plan.md`、`进展.md`、`decisions.md`）的读写权限；
   - **子 Agent 绝对严禁修改 `flow/` 目录**，防止状态机撕裂与写冲突。
2. **写入作用域完全隔离 (Disjoint Write Sets)**:
   - 派发前必须规划无交叠的文件修改边界（如子 Agent A 修改前端 Vue，子 Agent B 修改后端 Controller）；
   - 严禁多个子 Agent 竞争修改同一文件。
3. **双引擎自适应兼容 (Dual-Engine Fallback)**:
   - **引擎 A (原生直连环境)**: 底层网关支持 `multi_agent_v1` 时，调用 `spawn_agent` 派发并行轻量沙箱；
   - **引擎 B (中继代理环境)**: 若网关返回 `unsupported call`，自动降级为 Side Chat 模式（建议用户在侧边栏开 2~3 个独立 Task 线程并行执行）或主控严格单切片动态销账模式，绝不死磕。

## 🚨 核心铁律四: 代码落地硬门禁与收工完整性反查 (Execution Completeness Gate)
1. **禁止以文档代代码 (Code-First Gate)**:
   - 凡涉及功能开发与缺陷修复的需求，**严禁仅编写方案文档或分析报告即宣告结束**；必须在本地完成代码修改并通过自测。
2. **收工自检反查清单 (Stop Hook Completeness Check)**:
   - 收到 `【收工自检】` 拦截时，Agent 必须强制反查用户 Prompt：
     * [ ] 用户要求修改的代码文件是否已 100% 落盘并完成最小验证？
     * [ ] 派发的 Sub-Agent 是否已全部执行完毕并合并？
   - ⚠️ 若任一项未完成，**严禁宣称任务完结，严禁将未完工需求写为已完成**，必须立即调用工具继续写代码！

## 🚦 核心铁律五: 会话健康度监控与自动接力预警 (Session Relay Gate)
1. **会话单调递增不可逆铁律**:
   - LLM 对话历史是 Append-Only 线性追加的。磁盘文件 GC 只能保证新会话轻装上阵，但**无法抹除当前已发生会话中的历史 Token**；
   - 单会话交互超过 **8~10 个回合** 或 Token 超过 **10 万** 时，模型注意力必然发生衰退，容易引发工具调用语法退化与截断。
2. **自动触发会话接力预警 (Relay Alert)**:
   - 当单会话交互达 8 轮以上时，Agent 必须在汇报底部输出【会话接力预警卡】：
     `⚠️ [会话熔断预警] 当前会话已连续交互 N 轮（上下文已接近临界区）。核心成果已 100% 落盘实体，强烈建议在侧边栏点击 [+ New Task] 开新会话，读取 flow/进展.md 接力推进！`

## 🛡️ 核心铁律六: 本地修改先行与发版绝对受控协议 (Local First & Zero Auto-Deploy Gate)
1. **本地先行，全渠道覆盖**: 不论问题来源是本地测试还是 MCP 远程工单（`list_feedback` / `get_feedback`），排障与修复**一律必须优先且仅在本地工作区修改代码并闭环验证**；
2. **绝不自动发版**: 本地自测通过后仅置为 `[-] 待验收`，调用 `resolve_feedback` 时必须注明 `[本地已验证·未推线上]`；必须等待用户给出明确的**发版指令（如“确认发版”、“推线上”）后**方可执行线上部署；
3. **发版必记流水**: 发版后必须第一时间在 `flow/发版记录.md` 中完整登记发版流水。

## 🔍 核心铁律七: 探查预算门禁与代码智能感知 (Probe Budget & CodeGraph Gate)
1. **探查预算限制**: 代码排障与搜索工具调用次数严格限制在 **≤ 3 步**，探查超 3 步必须直接锁定根因动手修改，严禁全盘 `grep -rn` 扫盘与无边界全局遍历；
2. **CodeGraph 首选**: 查找函数、类、跨文件调用，优先执行 `codegraph explore "<关键词>"`（单次调用直接返回源码与行号）。

## 开工前必读
1. **用户当前指令**: 审读用户本回合具体诉求（最高优先级）
2. `flow/plan.md` 中的当前活跃 P0 任务（忽略 `[-]` 待验收项与其他模块任务卡）
3. `flow/进展.md` 顶部最新 1 条接力棒

## 收工前必做
1. 在 `flow/进展.md` 顶部追加一条进展（做了什么 / 产出路径 / 状态变化），并同时贴在回复中（严格滚动保留最新 1~2 条）。
2. **执行物理 GC**: 任务验收通过变为 `[✓]` 时，**立即执行物理剪切移入 `flow/history/`**。
3. 决策追加 `flow/decisions.md`；踩坑追加 `flow/踩坑记录.md`。

## 核心约束(铁律)
- 用户当面指令第一，严禁僵尸任务复读。
- 任务完成即物理剪切归档，活跃区零残留。
- 子要点做完即剥离注意力，仅加载未完成切片。
- 产出落盘实体，不留在口头；日常单点修改走快速通道，代码/配置落地即验证。
- 解决问题从根本上解，不打补丁。
