## 🎯 核心铁律一: 任务四状态机与首屏看板输出协议 (Task State Machine & Header Contract)
任务必须严格遵循四种状态，**且任何实质性回复第一屏必须强制输出【任务四状态机看板与提请验收卡】**：
1. **`[ ]` 待完成 (TODO)**: 当前会话用户指定的任务为 **最高优先级 (P0)**，立即执行；其余排队待办按需激活。
2. **`[-]` 待验收 (Pending Verification)**: 上一轮已交付、等待用户确认。**低优先级/绝对静默状态**，Agent **严禁自发重复执行、严禁反复排查、不要去管它**！
3. **`[✓]` 已完成 (Done)**: 用户验收确认通过，彻底完结。**必须立即从 `plan.md` 物理剪切移入 `flow/archive/`**，活跃看板零留存已完成文本。
4. **`[✕]` 不合格 (Rejected)**: 用户验收判定不合格。**最高优先级 (P0)**，本次会话必须立即针对缺陷进行重构修改，修复后转为 `[-]` 待验收。
5. **首屏看板与验收卡协议**: 回复第一段必须输出结构化看板（已归档/待验收/当前P0待办），本轮有交付必须显式给出【提请验收卡】，严禁把看板淹没在长文正文中。

## ⚡ 核心铁律二: 任务按需加载与动态销账机制 (On-Demand Loading & Dynamic GC)
1. **多子任务动态销账 (In-Prompt Pruning)**: 用户 Prompt 包含多个子要点（如点 1、点 2、点 3）时，Agent 必须维护当前焦点；**已完成的要点立即打上 `[✓ DONE -> PRUNED]` 并从当前注意力中彻底剥离，后续交互仅加载未完成项，严禁重复把全量已完成 Prompts 重新加载**。
2. **物理即时回收 (Mandatory Physical GC)**: 用户一旦确认通过，Agent 在当回合**必须第一优先执行文件剪切指令**将任务移入 `flow/archive/`，严禁口头归档但文件不剪切。
3. **待验收静默过滤**: 读取 `plan.md` 时自动忽略 `[-]` 状态项，不当做活动待办。
4. **归档区物理隔离**: 历史已完成任务物理存放于 `flow/archive/`，默认不读，彻底防止乱入需求与上下文污染。
5. **大文件按需嗅探 (Context Budget)**: 严禁无节制 dump 大型 HTML/源码全量入上下文，必须先用目录结构与轻量提取分析，防止上下文膨胀引发调用中断。
6. **快速通道 (Fast Track)**: 日常单点修改、UI 微调、单点 Bug 修复直接修改代码验证，不被重型流程阻碍。

## 开工前必读
1. **用户当前指令**: 审读用户本回合具体诉求（最高优先级）
2. `flow/plan.md` 中的当前活跃任务（仅看 `[ ]` 或 `[✕]`，忽略 `[-]`）
3. `flow/进展.md` 顶部最新一条接力棒

## 收工前必做
1. 在 `flow/进展.md` 顶部追加一条进展（做了什么 / 产出路径 / 状态变化），并同时贴在回复中。
2. **执行物理 GC**: 任务验收通过变为 `[✓]` 时，**立即执行物理剪切移入 `flow/archive/`**。
3. 决策追加 `flow/decisions.md`；踩坑追加 `flow/踩坑记录.md`。

## 核心约束(铁律)
- 用户当面指令第一，严禁僵尸任务复读。
- 任务完成即物理剪切归档，活跃区零残留。
- 子要点做完即剥离注意力，仅加载未完成切片。
- 审稿模型 ≠ 产出模型 (重大交付前换另一个模型评审)。
- 产出落盘实体，不留在口头；日常单点修改走快速通道，代码/配置落地即验证。
- 解决问题从根本上解，不打补丁。
