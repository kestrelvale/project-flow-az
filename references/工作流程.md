# 工作流程

> 五段式主循环 + 任务回收机制 + 用户即时指令优先 + 三个核心机制。这是"活儿怎么流动与终结"的详规。

---

## 核心铁律: 用户即时指令第一优先级 (Prompt Priority)

- **当前会话指令高于一切历史文档**: 用户在当前对话中下达的明确指令（如具体修改、范围约束、"不要历史需求"、"停止/跳过某任务"）是最高指令源。
- **严禁被历史任务绑架**: `flow/plan.md` 是宏观上下文与当前活跃契约，绝不是阻碍响应用户当下意图的锁链。当用户明确要求聚焦某个单点或跳过历史时，必须立即无条件以用户最新指令为焦点执行。
- **真相源在文件里的真实含义**: 系统的架构、配置与产出必须落盘为实体文件（不只留在口头），**绝不能歪曲为用历史文件中的旧计划去推翻或忽视用户当前的即时指令**。

---

## 核心机制: 任务生命周期与强制回收 (Task GC & Anti-Looping)

### 为什么任务必须回收归档？
如果不及时回收已完成任务，`flow/plan.md` 和 `flow/进展.md` 就会无限堆积历史。大模型的注意力（Attention）会被历史文字持续激活，导致**“反复来回执行已完成任务”、“死循环”、“僵尸任务复读”**。

### 回收与归档三大原则 (R-GC: 物理零留存)
1. **即时物理剪切 (Cut on Done)**:
   - 任务一旦完成，**必须立即从 `flow/plan.md` 中物理剪切移入 `flow/archive/`**！
   - `flow/plan.md` 严禁堆积 `[x]` 项，只保留当前待办 `[ ]` 或置为 `IDLE`。
   - `flow/tasks/` 下已完成任务卡立即移动至 `flow/tasks/archive/`。
2. **已完成任务物理隔离与防重入**:
   - 活跃区没有已完成任务的任何文本残留，彻底根除大模型上下文注意力被历史任务劫持的隐患。
3. **进展日志定期剪枝与轮转 (Log Rotation)**:
   - `flow/进展.md` 保持在最新 15~20 条以内（约 200 行以内），作为当前活跃接力棒。
   - 超出部分按月或按阶段自动剪切归档至 `flow/archive/进展_YYYYMM.md`，防止上下文膨胀造成模型注意力涣散。

## 任务执行双通道机制

根据任务规模自动分流，严禁微任务被重型流程绑架：

### 快速通道 (Fast Track: 日常即时修改 / UI调整 / 单点Bug / 用户指定范围)
- **特征**: 影响范围小、指令明确、即时性强（如改个按钮位置、修个数据缺失、改个菜单名称）。
- **执行方式**:
  1. 立即锁定用户指令范围，直接修改代码或数据；
  2. 就近运行必要验证；
  3. 极简收尾：在 `flow/进展.md` 顶部追加简明接力棒（或按需产出单份精简 Markdown），**不强制开辟重型全套流程**。

### 标准通道 (Milestone Track: 重大功能 / 新模块 / 跨系统重构)
- 走标准五段式主循环（立项 -> 拆解 -> 执行 -> 评审 -> 沉淀与回收）。

## 五段式主循环(重大任务走一遍)

### ① 立项
填 `flow/charter.md`: 目标 / 范围(做什么 + 不做什么) / 约束 / 成功标准 / 角色。
这是所有 Agent 开工要读的第一份; 模糊目标先在这里钉死。

### ② 拆解
出 `flow/plan.md`: 里程碑 + 任务拆解(每个任务标: 负责角色、输入、产出落哪、验收标准), 用户确认。
**计划即契约**——要偏离, 先改 `plan.md` 再动手。

### ③ 执行
每个终端一个角色, 读对应任务卡 `flow/tasks/T<编号>-<描述>.md` 开工。
- 可独立的任务并行 (git worktree / branch 隔离)。
- 小步、勤检查点。知识与方案产出落到根级 `docs/`; 代码落到对应子项目目录。

### ④ 评审
交付前**换另一个模型评审**(Codex 审 Claude, 或反之), 结论写 `docs/` 或任务卡。PASS / FAIL 才算过门。
**铁律: 审稿模型 ≠ 产出模型**。

### ⑤ 沉淀与回收 (强制执行)
1. 合并产出；
2. **任务回收**: 将本阶段已完成的 `flow/tasks/` 移入 `flow/tasks/archive/`；将已完结的 `plan.md` 内容归档至 `flow/archive/`；
3. 决策写 `flow/decisions.md`；问题 / 踩坑写 `flow/踩坑记录.md`；
4. 按 `文档维护SOP.md` 提炼长效规则更新至 `AGENTS.md`。

## 核心机制

### A. 进展日志 = 接力棒(Agent 接力的最小单位)
位置:`flow/进展.md`, **append、新的放最上面**。每个 Agent 干完一棒在顶部加一条; **顶部那条 = 当前交接棒**。
每条字段: **做了什么 / 为什么 / 怎么理解 / 产出(路径) / 问题→解决 / 下一步**。
- 收工时这条**既写进文件、也贴在回复里**——用户当场看到 + 可直接复制。
- **铁律: 只带「指针 + 增量」**——指向真实产出(给路径)+ 这一棒新增, **不重抄内容**。

### B. 分层入口 = 运行时合同
根级 `AGENTS.md` 是总体合同，写跨模块的精要规则、约束、目录地图和指针；根级 `CLAUDE.md` 软链到它。单仓多子项目中，每个有独立职责的模块再建局部 `AGENTS.md` + `CLAUDE.md` 软链。

### C. 跨模型评审
Claude Code = 主控(持上下文 / 编排); Codex = 独立第二双眼睛。
模式: 生成→评审 / 对抗找茬 / 第二意见。

## 目录归属(R1)
| 文件夹 | 放什么 |
|---|---|
| 根级 `flow/` | 唯一控制层: charter / plan(仅保留当前活跃契约) / 进展(最新接力棒) / decisions / 踩坑记录 / tasks / archive(已回收归档区) / 规范副本 |
| 根级 `flow/archive/` | **已完成阶段计划、历史任务卡与过期进展日志的回收归档隔离区** |
| 根级 `docs/` | 集中内容层: 产品 / 架构 / `contracts/` 跨模块契约 / `modules/` 模块说明 / 评审与产出说明 |
| `<module>/`、`scripts/`、`src/` | 代码、测试、构建与运行配置 |
| 根级 `AGENTS.md` | 总体运行时合同(含用户指令优先、防重入、任务回收机制) |
| `<module>/AGENTS.md` | 有独立职责子项目的局部合同; 同目录 `CLAUDE.md` 指向它 |
| `DESIGN.md` | (可选)设计 / 创意决策 |
