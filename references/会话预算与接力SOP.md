# 会话预算与接力 SOP

本文件只在 `flow-boot.py` 报告会话预算 WARN 或 STOP，或用户明确询问上下文/token 消耗时加载。

## 交接是三段链，不是单点功能

多任务并行的核心风险是：单个会话越跑越大，最后被上下文撑爆、任务烂尾。为此交接拆成三段，缺一段就断链：

| 段 | 位置 | 由谁执行 | 作用 |
|---|---|---|---|
| ① 会话内监控 | `flow-budget.py` | 每轮 `flow-boot.py` 自动调用 | 读真实 token 用量，判定 OK / WARN / STOP |
| ② 生成接力提示词 | `flow-budget.py` | WARN / STOP 时自动输出 | 给新会话一段可直接复制的启动指令 |
| ③ 新会话校验交接棒 | `flow-boot.py` | 新会话开工首动 | 校验顶部交接棒四字段，不合格直接拦出 |

### ① 会话内监控

详细字段与阈值见下两节。要点：**读的是 session jsonl 里的真实 usage，不是模型自我估计。**

### ② 生成接力提示词

达到 WARN / STOP 时，`flow-budget.py` 输出一段可直接复制的提示词，包含：

- 新会话的第一条命令（带 `--intent` 的 `flow-boot.py`）；
- **只读取白名单**：`flow/plan.md` 聚焦项、`flow/进展.md` 顶部一条、当前任务卡、匹配的 `flow/规范/*.md`；
- 上一会话熔断的真实数据（单次输入 / 缓存命中 / 上下文占用 / 轮次 / 工具调用）；
- 关键约束：**以磁盘真实状态为唯一真相源，不复读历史聊天，不读 `history/` 与 `trash/`**。

### ③ 新会话校验交接棒（强制，不可跳过）

新会话开工时，`flow-boot.py` 检测到上一轮以 STOP / 熔断收尾，会强制校验 `flow/进展.md` 顶部交接棒：

**必须在「路由阻塞」拦出以下两种情况：**

1. **缺字段**：必须写全「现状 / 还剩 / 卡在哪 / 下一步」四字段；
2. **超长**：单条交接棒超过 1200 字节——过长说明在复述背景，而不是交接状态。

**另由 `flow-distill.py handoff` 拦出第三种（v4.15.0 起）：**

3. **非蒸馏**：交接棒里没有规格点(SPE-n)/待办(TODO)结构，或与用户消息的照抄比例 >= 60%、
   最长连续照抄 >= 400 字符——即「原样照抄用户消息」。这类交接等于把历史复述一遍，
   新会话只能重读全部历史；上下文一旦进入压缩区，压缩摘要把整段历史回放成「汇报」，
   用户看到的就是自己的话被原样贴回来。

交接棒标准格式：

```markdown
## YYYY-MM-DD · <任务> · <谁>
- 现状: <已做到哪，具体到文件路径或 Exit 0 命令>
- 还剩: <未完成项清单>
- 卡在哪: <熔断原因 / 缺什么 / 无>
- 下一步: <接手方第一条具体命令>
```

**为什么必须强制**：交接棒若只写“下一步做什么”，不写“已做到哪、还剩什么、卡在哪”，
新会话就得重读 `plan.md` + 任务卡 + 全部进展才能拼出状态——这部分是纯重复劳动，
等于把熔断的成本再付一遍。实测 o2o 的进展文件涨到 86KB 时，新会话光还原现场就烧掉大半预算。

## 数据来源

`flow-boot.py` 每轮调用 `scripts/flow-budget.py`，从当前 `CODEX_THREAD_ID` 对应的 Codex session jsonl 读取真实 `token_usage_record` 与 `token_count`。

报告字段：

- `单次输入`：最近一次模型请求的 `input_tokens`，这是当前上下文压力的主要指标；
- `缓存`：最近一次请求的缓存命中比例；
- `窗口`：当前会话记录的 `model_context_window`；
- `轮次`：当前 thread 的 `task_started` 数量；
- `工具调用`：当前 thread 生命周期内去重后的工具调用数量，用于判断该会话是否已经积累过多次“带全量上下文请求”；
- `累计输入`：thread 生命周期内的总输入 token，只用于成本追溯，不作为当前上下文长度。

不把 `turn_token_usage` 当单次上下文长度，因为一个 turn 可能包含多次模型请求和工具调用；它只用于累计成本观察。

## 阈值

| 级别 | 触发条件 | 动作 |
|---|---|---|
| OK | 上下文占用 < 45%，轮次 < 15，工具调用 < 90 | 正常按路由施工 |
| WARN | 上下文占用 >= 45%，或轮次 >= 15，或工具调用 >= 90 | 回上游 `flow/plan.md` 按 SDD 拆卡，停止扩大读取范围，准备交接 |
| STOP | 上下文占用 >= 50%，或轮次 >= 25，或工具调用 >= 160 | 柔性阻塞：本轮只允许交接落盘，禁止登记新意图与业务施工 |

**为什么是比例而不是绝对值**：窗口 = 模型 `context_window` × `effective_context_window_percent`，
也就是会话里 `model_context_window` 的值。实测中继会话一律 **950000**（=0.95×1e6），
原生 GPT 是 **258400**（=0.95×272k）——同一个绝对值对两者必然一个太紧一个太松。

**45% 怎么来的（2026-09-23 取证 8 个分端会话）**：

| 实测项 | 数值 | 占窗口 |
|---|---|---|
| 压缩安装成功时的单次输入 | 996370 | 104.9% |
| 模型开始**回放用户消息**的单次输入（先失效的是模型，不是压缩） | 556166 / 574491 / 608167 | **58.5%** |
| 单轮上下文增量 p50 / p90 / max | 30982 / 125246 / 289972 | p90 = 13.2% |

按推导，留一个 p90 轮的线是 58.5% − 13.2% ≈ **45%**。**用户 2026-09-23 拍板采用
WARN 45% / STOP 50%**（要用满窗口）——这是知情取舍：50% 时距失效起点只剩 8.5% 窗口
= 950k 下 8.1 万 tokens，而单轮增量 p90 是 12.5 万，即**余量约 0.65 个 p90 轮**
（45% 时是 1.03 个轮）。也就是说 STOP 线附近的一个中等偏重轮次就可能越过失效点。
落到各模型：有效窗口 258400 → STOP 12.9 万；190000 → 9.5 万；353400 → 17.7 万；
950000 → 47.5 万。

窗口读不到时（session 缺 `model_context_window`）才退回绝对值：WARN 42 万 / STOP 47 万
（按实测中继窗口 950k × 45% / 50% ≈ 42.8 万 / 47.5 万）。旧值「工具调用 >= 100」曾在单次输入仅 38% 时
误报 STOP，把熔断降级成噪音，已上调到 160。

## 中段复查（不装 Hook 的替代）

开工那一次预算判定会随 turn 变长而过期：实测 P4 会话在**同一个 turn 内**跑了 200+
次工具调用，全程没有再判一次，一路堆到单次输入 60.8 万才被模型自己"摆烂"暴露。
AGENTS.md 规定不装 Hook，所以复查只能做成一条可被明确调用的命令：

```bash
python3 ~/.codex/skills/project-flow-az/scripts/flow-budget.py --guard --project .
```

**节奏：每 50 次工具调用复跑一次**；未超线返回 0 并提示节奏，超线返回非零并打印强制动作
（蒸馏交接棒 → 开新会话）。`--guard` **不写熔断回执**——回执由开工那一次判定负责，
否则每 50 次调用刷一条，`flow/budget/` 会被重复回执淹没、"最近一次 STOP"判定失真。

## 柔性阻塞（未交接的熔断）

上一轮 STOP 回执没有被交接棒核销时，`flow-boot.py` 把本轮路由降级为 **handoff-only**：
只允许写交接棒与 `flow/specs/<ticket>.md` 规格点台账，**拒绝登记新意图、拒绝进入 Execute 施工**；
进程本身不失败（柔性），补上规范交接棒后自动解除。

## STOP 标准动作

1. 停止新增业务实现和大范围读取；
2. 将当前已完成的修改落盘，确保不留下无法解释的半成品；
3. 在 `flow/进展.md` 顶部写一条**SDD 蒸馏**交接棒，并更新 `flow/specs/<ticket>.md`
   规格点台账（逐条回收状态；完成项必须带证据）。交接棒禁止原样照抄用户消息，
   只写规格点(SPE-n) / 待办(TODO) / 证据 / 下一步。包含：
   - 当前活跃 ticket；
   - 已回收的规格点（编号 + 证据）；
   - 未回收的规格点（编号 + 为什么没做完）；
   - 写入白名单；
   - 验证命令和当前结果；
   - 下一步第一个动作；
4. 使用 `flow-budget.py` 输出的接力提示词开启新会话；
5. 新会话首动继续运行带 `--intent` 的 `flow-boot.py`，只读取活跃任务卡、进展顶部一条和匹配规范。

## 规格点回收（中断后不重复执行）

- 台账位置：`flow/specs/<ticket>.md`，每行 `- [状态] SPE-n | 规格点 | 证据：<…>`；
  状态为 `[ ]` 未做 / `[-]` 进行中 / `[x]` 完成 / `[!]` 阻塞。
- `flow-distill.py spec` 校验台账：格式错、编号重复、**标 `[x]` 却没证据（假销账）** 一律 Exit 1。
- `flow-deliver.py` 交付时自动附 `### ♻️ 规格点回收` 段；台账不合格直接拒绝交付（Exit 1）。
- 续跑口径：**只做未回收项，标记 `[x]` 的完成项不得重跑**。
- 交接棒蒸馏校验：`flow-distill.py handoff --thread-id <id>` 对交接棒与用户消息做照抄比对，
  照抄比例 >= 60% 或最长连续照抄 >= 400 字符即判「原样照抄用户消息」并 Exit 1。

## 为什么不能只靠模型感觉

不同模型的窗口和缓存命中率不同，长会话中每一次工具调用都会重新携带上下文。只有读取 session jsonl 里的真实 usage，才能区分：

- 是单次上下文过长；
- 是轮次过多；
- 是工具调用过多；
- 是缓存命中率下降；
- 还是累计成本高但当前上下文并不高。

## 降级行为（重要边界）

`flow-budget.py` 依赖读取 Codex 客户端本地的 `~/.codex/sessions/**/*.jsonl`。
这是客户端自有格式、不是公开协议，大版本升级可能改变结构。

**设计上保证降级安全**：读不到 session 文件时，脚本输出提示并返回 0，
**不阻塞施工**，只是失去预算预警。监控是增强项，不是施工的前置条件。
