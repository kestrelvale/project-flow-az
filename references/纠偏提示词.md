# project-flow 纠偏提示词（v4.15.4）

**用途**：把下面代码块整体贴给需要纠偏的分端会话（P0 / P2 / P3 / P4 / P5 / P6 / P-FRONT / P\*），
把 `<端名>`、`<ticket>` 换成实际值即可。一次会话贴一次，不用重复贴。

**为什么需要它**：门禁与阻塞只能拦住「不合规的产物」，拦不住「用旧口径继续施工」。
这份提示词负责把口径一次性切换干净。**注意：不纠偏不是「建议没被采纳」，是过不了门禁**——
规格点台账缺失或有未回收项，`review` 阶段直接失败；交接棒照抄用户消息则熔断不会核销，
会话会一直被柔性阻塞挡在 handoff-only。

**适用版本**：`flow/规范/VERSION` 必须已热同步到 **4.15.4**。

```text
【纠偏指令 · project-flow v4.15.4 · 立即生效】
你的执行逻辑必须按下面切换。旧口径全部作废：75%/90% 阈值、28 万绝对值阈值、
只写「现状/还剩/卡在哪/下一步」的交接棒、不带台账的收工。

0. 硬首动（第一条工具调用，不得跳过）
   python3 ~/.codex/skills/project-flow-az/scripts/flow-boot.py . --intent "<本轮任务>"
   首屏必须报：当前聚焦 / 路由阻塞 / 未纳管遗留 / 预算等级 / 是否【柔性阻塞】/ 未回收规格点。
   并确认 flow/规范/VERSION 已热同步到 4.15.4；没同步先同步，再动任何代码。

1. 预算口径（窗口相对，不是绝对值）
   有效窗口 = 会话里的 model_context_window。中继模型通常 950000，原生 GPT 是 258400。
   - WARN = 有效窗口 45%   （950k → 42.75 万；258.4k → 11.6 万）
   - STOP = 有效窗口 50%   （950k → 47.5 万；258.4k → 12.9 万）
   - 规模兜底：轮次 >= 15 警告 / >= 25 停止；工具调用 >= 90 警告 / >= 160 停止。
   - 中段复查：每 50 次工具调用必跑一次（不装 Hook，这是唯一手段）
     python3 ~/.codex/skills/project-flow-az/scripts/flow-budget.py --guard --project .
     返回非零 = 立即停止扩展实现、转交接。

2. 柔性阻塞（不是建议，是路由被降级）
   触发：上一轮熔断回执未核销，或距上次检查点已过 50 次工具调用。
   后果：本轮只允许「交接落盘」——写交接棒 + 写规格点台账；
        禁止登记新意图、禁止开新 Execute 卡、禁止业务施工、禁止启停服务。
   交接提示词（随时可取回，不必自己拼）：
     python3 ~/.codex/skills/project-flow-az/scripts/flow-budget.py --print-relay --project .
     （优先打印最近熔断回执里存的那份；开工被阻塞时 flow-boot 也会直接贴出来）
   解除：交接棒与台账落盘并通过校验后，新会话开工自动核销。
   注意：写一句占位标题糊过去无效——核销要走校验（字段 + SDD 蒸馏结构 + 非照抄）。

3. 交接必须是 SDD 蒸馏产物（禁止原样照抄用户消息）
   - flow/进展.md 顶部只写：规格点(SPE-n) / 待办(TODO) / 证据 / 下一步。
   - 硬判据：与用户消息「最长连续照抄 >= 400 字符」或「照抄比例 >= 60%」即判为原样照抄，交接不成立。
   - 为什么：会话一旦进压缩区，压缩摘要把全部历史用户消息回放成「汇报」，
     你就会把用户说过的话原样贴回来，新会话只能重读全部历史。
     实测 P4 会话正是这样把 12942 字符的历史复述当成了汇报。

4. 规格点回收台账（中断后不重复执行的唯一依据）
   - 位置：flow/specs/<ticket>.md，行格式（正则严格，不要改）：
     - [ ] SPE-1 | <规格点：可观察的结果> | 证据：<可复现凭证>
     状态：[ ] 未做 / [-] 进行中 / [x] 完成 / [!] 阻塞；[x] 必须带证据。
   - 门禁：进入 review/handoff 前台账必须存在且无未回收项；假销账（[x] 无证据）直接拦。
     确实无规格点的琐碎卡，才写 spec_ledger: none 豁免（留痕，不是静默放行）。
   - 续跑口径：只做未回收项，标记 [x] 的完成项不得重跑。
   - 交付：flow-deliver.py 会自动附「规格点回收」段，逐条回收状态与证据。

5. 外部巡检（每 15 分钟）
   本机已装 LaunchAgent `com.projectflow.heartbeat`，扫活跃 project-flow 会话的预算。
   收到「project-flow 预算告警」系统通知 = 该会话必须立即交接，不要等下一次开工。
   卸载：launchctl unload -w ~/Library/LaunchAgents/com.projectflow.heartbeat.plist

6. 汇报格式（只写这些，不复述历史）
   做了什么 / 为什么 / 产出路径 / 证据（Exit 0 原文）/ 阻塞 / 下一步。
   收工必须跑 flow-deliver.py，并把「任务状态看板 + 本轮工作汇报 + 交付验收卡」原样粘贴。

7. 禁止
   禁止改 P3/P5/P6/P2 的边界、禁止改 OpenAPI/RBAC/状态机/金额规则、禁止启停服务、
   禁止 git push / reset --hard、禁止对 worktree 执行 git checkout -- . / git clean -fd。
```

**版本历史**：v4.15.0 首次给出（规格点回收 + SDD 蒸馏交接）；v4.15.2 加入柔性阻塞与 45% 阈值；
v4.15.3 加入台账硬门禁与检查点；v4.15.4 加入外部心跳与只读巡检。
