# 任务四状态机与按需加载 SOP (Task State Machine & On-Demand Loading SOP)

> 解决 Agent 历史包袱过重、旧任务反复执行、乱入需求干扰与验收不闭环的根本方法论。

---

## 1. 任务四状态机定义 (The 4 Task States)

```
        ┌─────────────────────────────────────────────────────┐
        │                 [ ] 待完成 (TODO)                    │
        │  用户本次下达(最高P0) / 待办排队(按需激活)            │
        └──────────────────────────┬──────────────────────────┘
                                   │ Agent 执行交付
                                   ▼
        ┌─────────────────────────────────────────────────────┐
        │                [-] 待验收 (Pending)                  │
        │  已交付，等待用户确认。Agent 绝对静默，不要去管！   │
        └──────────────┬───────────────────────▲──────────────┘
                       │                       │
         用户验收通过   │                       │ 用户判定不合格，指出缺陷
                       ▼                       │
        ┌──────────────────────────┐   ┌───────┴──────────────┐
        │      [✓] 已完成 (Done)    │   │    [✕] 不合格 (Fix)   │
        │  彻底完结，物理移入归档区  │   │  最高优先级P0，立即修改 │
        └──────────────────────────┘   └──────────────────────┘
```

### (a) `[ ]` 待完成 (TODO)
- **定义**: 尚未开始或正在进行中的任务。
- **调度规则**:
  - **当前会话任务 (Focus Task)**: 用户在当前对话中下达的任务，**优先级最高 (P0)**，必须立即执行！
  - **排队任务 (Backlog Task)**: 后续规划任务，处于待命排队状态，不抢占当前焦点。

### (b) `[-]` 待验收 (Pending Verification)
- **定义**: 上一轮已经执行完毕并交付产物，但**用户尚未明确确认是否合格**的任务。
- **调度规则**:
  - **低优先级 / 绝对静默**：Agent **严禁自发重复执行、严禁重新扫描排查、严禁当成待办任务去处理**！
  - 仅作为状态看板展示，静默等待用户验收反馈。

### (c) `[✓]` 已完成 (Done)
- **定义**: 用户在验收过程中明确确认合格、彻底完结的任务。
- **调度规则**:
  - **物理剪切归档 (Instant Task GC)**: 验收通过后，**立即从 `flow/plan.md` 活跃区物理剪切移入 `flow/archive/`**，活跃文件物理禁止留存已完成文本，消除上下文污染。

### (d) `[✕]` 不合格 (Rejected / Needs Revision)
- **定义**: 用户在验收过程中指出问题、判定不合格的任务。
- **调度规则**:
  - **最高优先级 (P0)**：Agent 收到反馈后，**必须在当前会话中立即定位原因并进行修改重构**，修复完成后再次转为 `[-] 待验收`。

## 2. 任务按需加载机制 (On-Demand Loading)

### 2.1 为什么必须按需加载？
全量加载历史任务是导致 Agent “注意力涣散、死循环、被乱入需求带偏”的根本原因。
模型上下文必须保持极高信噪比。

### 2.2 按需加载三大准则
1. **焦点最小化**: 开工时，仅装载与当前任务直接相关的输入、契约与代码路径；
2. **历史隔离化**: `flow/archive/` 历史归档文件默认**绝不主动加载**；
3. **状态过滤化**: 读取 `flow/plan.md` 时：
   - 聚焦处理 `[ ]` (当前任务) 与 `[✕]` (不合格重修任务)；
   - 过滤忽略 `[-]` (待验收任务) 与已归档内容。

---

## 3. 闭环验收操作流 (Acceptance Loop)

1. **执行交付**: Agent 修改代码/产物并验证后，将该任务在 `plan.md` 中标记为 `[-] <任务描述> (已交付待验收)`；
2. **用户验收**:
   - 若用户确认 OK -> Agent 将该项标记为 `[✓]` 并**立即剪切移入 `flow/archive/`**；
   - 若用户指出不合格 -> Agent 将该项标记为 `[✕]`，并作为本轮最高优先级任务立即修改。
